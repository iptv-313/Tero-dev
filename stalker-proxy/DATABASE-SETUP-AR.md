# تشغيل قاعدة بيانات TeroDev Proxy وربط تطبيق Android

## شنو هي قاعدة البيانات؟

الملف `stalker-proxy/database.sqlite` هو قاعدة **SQLite**؛ ما تحتاج تثبّت MySQL أو PostgreSQL. عند تشغيل البروكسي، يفتح الملف تلقائياً وينشئ الجداول الناقصة إذا احتاج.

يحتوي على جدولين أساسيين:

- `access_codes`: رموز الدخول وصلاحيات المستخدمين والمديرين.
- `portals`: أسماء بوابات Stalker وروابطها وعناوين MAC.

القنوات والأفلام والمسلسلات ما تنحفظ بملف SQLite؛ البروكسي يجلبها من بوابة Stalker عند الاتصال.

## تشغيل البروكسي على جهازك

من مجلد المشروع افتح Terminal ونفّذ:

```bash
cd stalker-proxy
cp .env.example .env
npm install
npm start
```

إذا ملف `.env` موجود مسبقاً لا تستبدله. عند ظهور رسالة تشغيل الخادم، افحص:

```text
http://localhost:3001/health
```

المفروض يرجع JSON بحالة `ok`. مجرّد تشغيل `npm start` يفعّل قاعدة البيانات؛ ما تحتاج أمر import إضافي.

## ربط تطبيق Android

1. شغّل البروكسي على جهاز أو استضافة يمكن لجهاز Android TV الوصول إليها. `localhost` داخل التلفزيون يعني التلفزيون نفسه، مو حاسوبك.
2. للإنتاج استخدم عنوان **HTTPS** عام؛ لا تفتح منفذ قاعدة البيانات للإنترنت، افتح منفذ تطبيق Node فقط.
3. افتح تطبيق TeroDev TV ثم **الإعدادات → TeroDev Proxy → تسجيل الدخول**.
4. أدخل عنوان البروكسي (مثل `https://proxy.example.com`) ورمز الدخول الموجود بجدول `access_codes`.
5. اختر البوابة المطلوبة واضغط **اتصال ومزامنة**. يحمّل التطبيق Live TV والأفلام والمسلسلات إلى قاعدة التطبيق المحلية.
6. إذا كان رمزك مديراً، يظهر زر **لوحة الإدارة**. من هناك تقدر تضيف/تحذف رموز الدخول والبوابات.

رمز الدخول يُخزّن مشفّراً باستخدام Android Keystore. تشغيل الوسائط يتم بتذكرة عشوائية مؤقتة يصدرها البروكسي بعد التحقق؛ ما يتم وضع رمز الدخول في رابط الفيديو.

## قاعدة جديدة فارغة

ماكو رمز مدير افتراضي ثابت. إذا أنشأت قاعدة جديدة وما بيها أي رمز، عيّن `INITIAL_ADMIN_CODE` إلى قيمة طويلة وسرية لأول تشغيل. بعد ظهور رسالة نجاح إنشاء المدير، احذف المتغير من إعدادات الاستضافة؛ الحساب يبقى محفوظاً داخل SQLite. لا تستخدم رمزاً عاماً مثل `123456`.

القاعدة المرفقة قد تحتوي رموزاً وبوابات محفوظة مسبقاً؛ استخدم بيانات الدخول التي تملكها، ولا تنشر الملف أو محتواه.

## عند النشر على استضافة

- اربط **Persistent Volume** حتى لا تختفي SQLite بعد إعادة النشر.
- عيّن `DB_PATH` لمسار داخل القرص الدائم.
- استخدم HTTPS، واجعل `ALLOWED_ORIGIN` عنوان موقعك الدقيق بدلاً من `*` إذا تستخدم الواجهة الويب.
- خذ نسخة احتياطية خاصة من `database.sqlite` ولا ترفعها إلى مستودع عام.
- لا تشارك ملف `.env` أو رموز الدخول أو MAC أو روابط البوابات.
